# 预算编制分层规则方案

> 面向不同层级参与预算编制的规则化 + 量化 + AI 推理模型
> 版本：v1（讨论稿） · 日期：2026-08-24 · 作者：松哥（方法论）/ WorkBuddy（整理）

---

## 0. 这份文档要解决什么

中国企业、尤其是集团型企业的预算管理，监管要求（财政部《管理会计应用指引——预算管理》、国资委相关制度）反复强调几条：

- 预算目标要**和战略衔接**
- 业务预算要和财务预算**衔接**
- 上下级预算要**平衡**
- 预算执行要有**约束**
- 执行后要有**分析和考核**（差异分析）

但落到系统里，如果只把"原则"写进需求文档，系统仍然只是"财务填表工具"。

本方案的主张是：**把预算经验拆成可量化、可判定、可质询的规则**，并用一个分层参与模型，让不同角色在编制流程的不同环节分别承担"填报 / 论证 / 汇总 / 决策"的职责。

最终目标：约 70%–80% 的预算项目先由规则和模型判断，剩下 20%–30% 的特殊情况再交给 AI 解释、质询和人工决策。

## 1. 八类预算规则（规则引擎视角）

> 每条规则给出：**量化公式 / 判定阈值 / 输出结论 / AI 追问方式**。
> 这是规则库的"骨架"，后续可展开为 20–30 条细粒度规则（见第 6 节）。

### 规则 1 · 历史基准规则（先回答"正常情况下应该花多少"）

**核心主张**：预算不应从"去年预算"出发，应优先从"历史实际消耗"出发。否则会出现典型的中国企业弊病——去年报高了 → 今年以高预算为基数 → 预算越来越虚。

**公式**：
```
预算基准 = 历史实际值 × 业务量变化系数 × 价格变化系数 × 管理改善系数
```
**示例**：
```
2024 实际 100 万 → 2025 实际 108 万
2026 业务量 +8%，价格 +2%，公司要求降本 -5%
基准预算 = 108 × 1.08 × 1.02 × 0.95 ≈ 113 万
```

**阈值**：申报值偏离历史基准超过 ±10%（可调），进入解释状态。
**AI 追问**："你的申报比历史基准高 X 万，请说明业务量/价格/改善系数中哪一项未体现？"

---

### 规则 2 · 趋势规则（不能只看上一年，看 3 年趋势）

**核心主张**：单看同比容易误判，要看 CAGR（复合增长率）和业务驱动是否匹配。

**公式**：
```
预算增长率偏离度 = 申报增长率 − 历史平均增长率（CAGR）
```
**示例**：
```
差旅费：2023 800万 → 2024 920万 → 2025 1080万（CAGR≈16%）
2026 申报 1500万（同比 +39%）
偏离度 = +23 个百分点
```
**阈值**：偏离度超过 15 个百分点，强制提供业务驱动因素（人员增长、出差次数、客单价等）。
**AI 追问**："历史 CAGR 16%，你申报 +39%，多出的 23 个点对应了哪些可验证的业务增量？"

---

### 规则 3 · 业务驱动规则（预算真正应该建立的核心）

**核心主张**：预算 = 数量 × 单价 × 业务活动，而不是"去年 1000 万，今年给 980 万"。

**公式族**：
```
差旅费   = 出差人数 × 人均出差次数 × 平均天数 × 日均成本
招聘费   = 招聘人数 × 单位招聘成本
车辆费用 = 车辆数 × 单车运行成本
培训费   = 培训人数 × 人均培训成本
食堂预算 = 就餐人数 × 人均餐标 × 工作日
办公费   = 人数 × 人均办公费
```
**阈值**：预算增长 % 与核心业务量增长 % 不匹配（差额 > 阈值），进入质询。
**AI 追问**："你的预算增长 20%，但人员只增长 3%，这 17 个点的差异来自哪里？"

---

### 规则 4 · 弹性规则（不同项目不能用同一种控制方式）

**核心主张**：预算至少分四类，审核逻辑完全不同。

| 类型 | 例子 | 预算方法 | 弹性系数 E |
|------|------|----------|-----------|
| 刚性 | 房租、物业、固定合同 | 合同驱动 | 不适用（直接读合同） |
| 半刚性 | 食堂、水电 | 人数/业务量驱动 | 低 |
| 弹性 | 差旅、招待、会议 | 历史+业务驱动+控制目标 | 高 |
| 项目型 | 搬迁、装修、大型活动 | 事件驱动 | 不适用（走 Event） |

**公式**：
```
预算允许增长率 = 业务增长率 × E + 价格因素
```
**阈值**：弹性费用上涨超过"业务增长 × E + 价格"的，进入质疑；刚性费用直接比对合同。
**AI 追问**："房租上涨 30% 若是新租赁合同约定则合理；差旅上涨 30% 但收入仅 +5%、人数未增，请解释。"

---

### 规则 5 · 横向对标规则（同类部门之间比较）

**核心主张**：比单纯同比更厉害的是同类型、同规模、同地区横向比较。

**指标族**：
```
人均费用   = 费用 / 平均人数
费用率     = 行政费用 / 营业收入
单店费用 / 单位面积费用 / 单车费用 / 每百万元收入差旅费
```
**公式**：
```
偏离倍数 = 本单位指标 / 集团同类中位数
```
**示例**：
```
集团人均行政费中位数 4200 元/人
D 公司 8700 元/人 → 2.07 倍
```
**阈值**：偏离倍数 > 1.5 倍（可调），进入重点审核。
**AI 追问**："D 公司人均费用是集团同类中位数的 2.07 倍，请说明差异的业务合理性。"

---

### 规则 6 · 总量控制规则（自下而上和自上而下必须碰一次）

**核心主张**：子公司报上来总和 1.2 亿，但集团战略要求 ≤1 亿，不能简单"统一砍 16.7%"，要按合理程度差异化压降。

**公式**：
```
压降潜力 = 历史浪费程度 + 横向偏高程度 + 非刚性比例 + 执行偏差程度
最终预算 = 基础预算 + 战略预算 + 必要项目 − 改善空间
```
**示例**：A 建议压降 3% / B 8% / C 18%，而非一刀切 10%。
**阈值**：单元压降潜力评分高于集团均值，优先下达压降目标。
**AI 追问**："C 公司压降潜力评分最高（横向偏高 + 执行偏差大），建议压降 18%，是否接受？"

---

### 规则 7 · 预算准确性规则（过去"报得准不准"应影响下一年）

**核心主张**：乱报预算应该有成本。

**公式**：
```
准确率     = 1 − |实际 − 预算| / 预算
可信度评分 = 40%×去年准确率 + 30%×前年 + 20%×三年前 + 10%×其他因素
```
**示例**：预算 1000 万 / 实际 900 万 → 准确率 90%；实际 600 万 → 60%。
**阈值**：连续 2 年准确率 < 70%，下一年申报自动降低可信度权重，AI 质询增强。
**AI 追问**："你去年申报 1100 万但实际仅 700 万（准确率 63%），今年又报 1100 万，请重新论证。"

---

### 规则 8 · 重大事件规则（把"正常预算"和"事件预算"分开）

**核心主张**：总预算 = BAU（Business As Usual 正常经营）+ Event（新增事件）。

**公式**：
```
总预算 = BAU预算 + Event预算
BAU增长率 = (BAU预算 − 上年实际) / 上年实际
```
**示例**：
```
去年行政 8000 万，今年报 1 亿（+25% 异常）
其中：BAU 8200 万，Event 1800 万（新厂区/搬迁/300人扩编）
→ 剔除事件后正常仅 +2.5%
```
**阈值**：Event 占比 > 20% 或绝对值 > 阈值，必须拆分填报并附事件说明。
**AI 追问**："你申报 +25%，但 Event 占 18%，剔除后 BAU 仅 +2.5%。请确认 Event 清单完整。"

## 2. 六层推理模型（AI 预算审核的主干）

```
第一层 历史    去年花多少？三年趋势怎么样？
   ↓
第二层 业务    人数、收入、产量、门店、面积、车辆有没有变化？
   ↓
第三层 价格    工资、租金、油价、供应商价格有没有变化？
   ↓
第四层 事件    有没有新增项目、搬迁、扩张、合同变更？
   ↓
第五层 对标    和其他子公司相比合理吗？
   ↓
第六层 战略    集团今年要求增长、降本还是投入？
   ↓
       合理预算区间（不是一个数字）
```

**最终输出形态（示例）**：
```
部门申报预算：1,280 万元
模型合理区间：1,080 – 1,160 万元
偏高：120 – 200 万元
主要原因：
  · 人员增长仅 4%，预算增长 21%
  · 人均费用比集团同类单位高 32%
  · 去年预算执行率仅 78%
  · 未发现重大新增项目
AI 追问："请说明新增 120–200 万元的业务依据。"
```

## 3. 主公式（系统落地的总纲）

```
合理预算 = 历史基准
         × 业务变化系数
         × 价格变化系数
         × 管理目标系数
         + 新增事件(Event)
         − 可释放效率

叠加三个判断：
  纵向趋势（规则 2）  +  横向对标（规则 5）  +  战略约束（规则 6）
```

这条公式把规则 1/3/4/8 的量化部分与规则 2/5/6 的判断部分统一到一个框架，是规则引擎计算"合理区间"的入口。

## 4. 四层级参与模型（本方案核心）

> 把上面的八类规则 + 六层模型，映射到编制流程中各层级的**角色 / 职责 / 用什么规则 / 输入什么 / 输出什么 / 系统支撑**。

### 4.1 基层填报层（员工 / 基层费用责任岗）

| 维度 | 内容 |
|------|------|
| **角色** | 员工（staff）、基层费用责任岗（expense） |
| **核心职责** | 填报经济事项、月度分解、提供业务驱动因子 |
| **主要使用规则** | 规则 3（业务驱动，提供数量×单价）、规则 8（Event 拆分填报） |
| **六层对应** | 第二层（业务）、第四层（事件）的数据提供方 |
| **系统输入** | 经济事项明细、业务量（人数/次数/面积）、Event 清单及说明 |
| **系统输出** | 结构化申报单（含业务驱动因子，非单纯金额） |
| **AI 在此层的作用** | 引导式填报：自动问"人数变了没？有没有新增项目？"，把规则 3/8 的输入前置采集 |
| **权限** | 仅本人/本费用类型范围（scope=self） |

**设计要点**：这一层不该出现"金额拍脑袋"，系统强制要求填写业务驱动因子（规则 3 公式的右侧变量），否则无法提交。这是把"预算从金额转向业务"的关键入口。

---

### 4.2 部门编制层（部门经理 / 事业部负责人）

| 维度 | 内容 |
|------|------|
| **角色** | 部门经理（manager）、事业部负责人（buHead） |
| **核心职责** | 部门编制、业务驱动论证、执行率自证、提交汇总 |
| **主要使用规则** | 规则 1（历史基准）、规则 2（趋势偏离）、规则 3（业务驱动）、规则 7（准确性自证）、规则 8（Event） |
| **六层对应** | 第一层（历史）、第二层（业务）、第三层（价格）、第四层（事件）的论证方 |
| **系统输入** | 历史实际 3 年、业务量计划、价格假设、Event 清单 |
| **系统输出** | 部门预算草案 + 偏离度自检报告（规则 2 偏离度、规则 7 准确率） |
| **AI 在此层的作用** | 提交前自动跑规则 1/2/7：若偏离度 >15 个百分点或准确率 <70%，提示"先补充论证再提交" |
| **权限** | 本部门范围（scope=dept / group） |

**设计要点**：部门经理是"第一道论证关"。系统不是替他编，而是把规则 1/2/7 的判定结果反馈给他，让他自己补业务依据或下调申报，避免把"裸金额"直接甩给财务。

---

### 4.3 财务汇总层（财务 / 总经办 / 归口责任人）

| 维度 | 内容 |
|------|------|
| **角色** | 财务经理（finance）、总经办负责人（cooLead）、总经办预算管理员（cooAnalyst）、职能中心归口责任人（centerOwner） |
| **核心职责** | 汇总、对标、压降下达、准确性评分、归口科目审核 |
| **主要使用规则** | 规则 4（弹性分类）、规则 5（横向对标）、规则 6（总量控制/压降潜力）、规则 7（可信度评分） |
| **六层对应** | 第五层（对标）、第六层（战略落地）、规则 4/5/6 的执行方 |
| **系统输入** | 全量部门草案、集团同类中位数、战略总量天花板、历史准确率 |
| **系统输出** | 横向对标报告、压降潜力评分、差异化压降建议、归口科目审核结论 |
| **AI 在此层的作用** | 自动生成对标表（规则 5）+ 压降潜力分（规则 6），把"统一砍 10%"升级为"差异化下达" |
| **权限** | 全量/归口范围（scope=all / center / group） |

**设计要点**：这是规则 4/5/6 的主战场。财务不再手工比对，系统直接输出"谁偏高、偏高多少、建议压降几个点"，财务做的是判断和下达，而非计算。归口责任人（centerOwner）按职能中心（MC-01~MC-11）审核归口科目，与组织架构的"管理中心↔部门归口"直接挂钩。

---

### 4.4 决策层（总经理 / 集团）

| 维度 | 内容 |
|------|------|
| **角色** | 总经理（boss）、集团 CEO（ceo） |
| **核心职责** | 总量平衡、战略约束、重大争议决策、终审 |
| **主要使用规则** | 规则 6（总量平衡）、六层模型第六层（战略）、规则 5（对标异常终审） |
| **六层对应** | 第六层（战略）的最终裁决方 |
| **系统输入** | 财务汇总后的压降方案、战略总量目标、争议项（AI 标记的高偏离/高对标异常） |
| **系统输出** | 批准的预算总额、战略调整决策、争议项裁决 |
| **AI 在此层的作用** | 呈现"模型合理区间 + 偏离原因 + AI 追问记录"，支撑总经理做差异化的总量平衡，而非一刀切 |
| **权限** | 全局（scope=all / group） |

**设计要点**：决策层看到的不应是 100 张表，而是"集团总量 vs 战略天花板""哪些单元被 AI 标红、为什么""压降潜力分布"。六层模型的第六层在这里闭环——战略（增长/降本/投入）反哺第一到第五层的约束。

## 5. 与现有系统的衔接点（后续落系统时的接口）

> 本节不改动代码，仅标注本方案与 BadgetManager 现有模块的对应关系，供后续开发参考。

- **规则 1/2/7 的计算**：依赖 `economic_event`（历史实际）与 `unit_budget`（部门草案），现有数据模型已具备。
- **规则 3 的业务驱动**：依赖经济事项（events）绑定"数量×单价×业务活动"，当前 `events` 表已有 `center/subject/method`，需补业务量字段。
- **规则 4 弹性分类**：依赖科目弹性系数 E，可作为科目属性扩展（当前 `subjects` 表可加 `elasticity` 字段）。
- **规则 5 横向对标**：依赖组织树（organization）+ 多公司实际数据，与"11 管理中心↔部门归口"直接关联。
- **规则 6 压降潜力**：依赖 `collision`（碰撞/争议）与战略总量，对应现有 `collisionItems` 与 M5 碰撞调参。
- **规则 8 Event 拆分**：依赖预算编制草稿区分 BAU / Event，对应现有 `compile` 草稿结构。
- **六层模型 / AI 追问**：对应现有 AI Copilot（`BM.sendChat` + 建议卡片），可把"AI 追问"固化为规则触发后的标准质询话术。

## 6. 下一步：预算编制规则库（20–30 条）

本方案的第 1 节是"八类规则骨架"，落地为规则引擎时应展开为 20–30 条细粒度规则，每条严格按以下格式：

```
规则编号：R-xxx
所属类别：规则 1–8 之一
名称：
输入数据：（字段 / 来源表）
判断公式：（可计算表达式）
阈值：（触发条件）
输出结论：（通过 / 解释 / 质疑 / 拦截）
AI 追问方式：（标准话术）
适用层级：（基层/部门/财务/决策）
```

**建议拆分方向**（示例，非穷举）：
- 规则 1 → R-101 历史基准计算、R-102 预算基数虚高检测（申报 vs 历史实际）
- 规则 2 → R-201 三年 CAGR、R-202 偏离度判定、R-203 业务驱动匹配检查
- 规则 3 → R-301~R-306 各费用类型的业务驱动公式
- 规则 4 → R-401 弹性分类、R-402 刚性合同比对、R-403 弹性允许增长率
- 规则 5 → R-501 人均费用、R-502 费用率、R-503 单店/单车/单位面积、R-504 偏离倍数
- 规则 6 → R-601 压降潜力评分、R-602 差异化下达、R-603 总量天花板校验
- 规则 7 → R-701 准确率、R-702 可信度评分、R-703 连续偏低质询
- 规则 8 → R-801 BAU/Event 拆分、R-802 Event 占比阈值、R-803 事件说明完整性

这套规则库就是 BadgetManager 规则引擎的直接输入。

---

## 7. 小结

本方案把松哥提出的预算方法论结构化：

1. **八类规则**（历史基准 / 趋势 / 业务驱动 / 弹性 / 横向对标 / 总量控制 / 准确性 / 重大事件）——解决"可量化"。
2. **六层推理模型**——解决"AI 怎么审"。
3. **主公式**——解决"系统算什么"。
4. **四层级参与模型**——解决"谁在什么环节用什么规则"，把规则分配到基层填报 / 部门编制 / 财务汇总 / 决策层，各有主责与参与。
5. **规则库接口**——解决"下一步落系统怎么拆"。

核心结论不变：**合理预算 = 历史基准 × 业务变化 × 价格变化 × 管理目标 + 新增事件 − 可释放效率，叠加纵向趋势 + 横向对标 + 战略约束**。约 70%–80% 的预算项目先由规则和模型判断，剩余特殊情况交给 AI 解释、质询和人工决策。
