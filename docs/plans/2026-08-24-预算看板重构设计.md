# 预算看板重构设计（2026-08-24）

> 状态：🟡 设计定稿，待开发
> 来源：松哥口述需求（2026-08-24 晚）+ AskUserQuestion 拍板（4 项）
> 关联：`kanban.js`（现有三视图扁平版，本次重构）；`organization` 树（角色范围过滤基础）；`compile.js`/`rules.js`（同源预算数据）

---

## 0. 目标与边界

把现有「预算看板」（三视图平铺表格）重构为**按角色分层 + 三层时间粒度 + 双维度嵌套**的活波卡片看板。

**核心命题**：同一份预算数据，从"谁负责 / 花在哪 / 哪个时间"三个逻辑轴观察，且三轴相互嵌套。

**不做**（本次边界）：
- 不新增数据库表/字段（执行数据复用 `CATEGORIES.monthly` 与 `economic_event.monthly`；组织范围复用 `organization` 树 + `unit_budget.org_id`）。
- 不接 LLM（预警为确定性阈值规则）。
- 不改动编制/规则页既有逻辑。

---

## 1. 三层时间粒度（面包屑下钻）

```
2026 全年  ›  Q3  ›  9 月
```

- 顶部面包屑，三个层级可点击回退/前跳。
- 展示数据 = **当前周期切片**，非全年累计：
  - 年：12 个月汇总
  - 季：该季 3 个月汇总（Q1=1~3, Q2=4~6, Q3=7~9, Q4=10~12）
  - 月：单月
- 当期切片指标：预算值（当期）、已执行（当期实际）、偏差（执行−预算）、预警（执行率超阈值/超支趋势）。
- 默认进入「全年」。

---

## 2. 角色 × 数据范围（组织树过滤）

数据范围由 `organization` 树层级过滤，**非前端写死**。真实树结构：`HQ → BU-xx（事业部/unit）→ U-xx（生产单元/dept）`，另有 11 个 `type=center` 管理中心（经 `managedCenterId` 归口）。

| 角色 | 可见范围 | 过滤逻辑 |
|---|---|---|
| 事业部经理（manager，scope=dept） | 自己事业部 + 下属生产单元 | 取登录用户 `deptId` → 向上找所属 BU → 该 BU 及子孙 |
| 管理中心责任人（centerOwner） | 自己管理中心 + 下属单位 | 取 `managedCenterId` 对应的 center 节点 + 其归口单位 |
| 总经理（boss/ceo） | 全部 | 不过滤 |
| 财务经理（finance） | 全部 | 不过滤 |
| 员工（staff，scope=self） | 自己负责的项目/事项 | 仅 `unit_budget` 中 owner=自己 |

> 前端无真实用户→组织归属时，回退演示映射（沿用 `BM.EVENT_OWNERS`/`BM.RULE_OWNERS` 思路，补 `BM.USER_ORG` 演示表）。

## 3. 双维度嵌套（节点内嵌）

**方案 A（已拍板）：节点内嵌双维度。**

进入某个组织节点（事业部 / 中心 / 单位）后，该节点卡片内有一个小开关：
`按经济事项  |  按财务科目`

- **按经济事项**：该组织范围内，各经济事项（车辆维修/差旅费/…）当期预算/执行/偏差。
- **按财务科目**：同范围，按 `acctCode` 聚合（6602.11 总办办公费 / 6602.12 食堂 / …）。

两个维度是**同一份数据的两种切法**，非独立页面。组织范围在外层定，业务维度在内层切。

嵌套层级示意：
```
总经理视图（全部）
├─ 氮化镓事业部（BU-01）         ← 点开
│  ├─ [开关] 按经济事项 / 按财务科目
│  ├─ 厦门生产单元（U-01）        ← 继续下钻
│  │  └─ [开关] 按经济事项 / 按财务科目
├─ 射频事业部（BU-05）
...
管理中心视图（centerOwner）
├─ 生产管理中心（MC-03）
│  └─ 归口单位列表（按 managedCenterId 反查）
```

## 4. 展示内容（每个叶子/节点卡）

| 字段 | 含义 | 来源 |
|---|---|---|
| 预算值（当期） | 本周期预算 | `monthly[周期索引]` 求和 |
| 已执行（当期） | 本周期实际 | `CATEGORIES.monthly` / 单据汇总（demo 用 monthly 前 9 月） |
| 偏差 | 执行 − 预算 | 正=超支（红）/ 负=节支（绿）— 遵循松哥涨跌色约定（绿涨红跌为**国际惯例**，但本项目财务场景按**超支红/节支绿**语义着色，已在 compile 页统一） |
| 预警 | 执行率阈值 | 执行率 >100% 红；85%~100% 黄；<85% 绿（可调） |

卡片含：标题（节点/事项名）、预算/执行双数、偏差徽标、执行进度条（执行/预算）、预警角标。

## 5. 视觉调性（活泼）

- 卡片网格（`grid` 自适应），区别于现有纯表格。
- 状态色：超支红 `#d64545`、节支绿 `#1d9e75`、预警黄 `#f59e0b`。
- 环形/条形进度表达执行率。
- 面包屑 + 节点可点下钻，hover 微交互。
- 复用现有 design token（`--c-surface`/`--c-primary`/`--c-border`），不引入新框架。

## 7. 风险与待确认

- **真实用户→组织归属**：当前 `users` 表与 `organization` 的归属仅在 demo 层。若上线需后端 `users.org_id` 与 `organization` 关联（已有 `unit_budget.org_id`）。本次前端用 `BM.USER_ORG` 演示映射兜底，不阻塞。
- **执行数据口径**：demo 用 `CATEGORIES.monthly` 前 9 月模拟"已执行"，10~12 月为 0（预算未执行）。真实环境应接单据/执行流水。
- **管理中心归口**：`managedCenterId` 已落库（11 中心），centerOwner 范围 = 该 center + 其 managedCenterId 指向的单位。
