## 二、对齐结论（松哥 2026-08-25 拍板）

分组方案：**编制规则 = 基线比例 + 编制方式；监督规则 = 执行追踪 + 期末余量 + 超预算**

| 组 | 包含内容 | 数据来源 |
|---|---|---|
| 编制规则 | 控制基线比例（各 scopeKey 压降比例）+ 编制方式 | `baseline` 全部 + `flow` 中 `planMode` |
| 监督规则 | 执行追踪方式 + 期末余量处理 + 超预算处理 | `flow` 中 `trackMode` / `surplusAction` / `allowOverBudget` |

> 唯一边界点 `planMode`（编制方式）按业务语义归「编制规则」组，松哥确认。

## 三、设计方案

### 3.1 前端：`renderRuleCards` 分组包裹（`website/views/rules.js`）

保持版本卡头（`rv-head`）在顶部不变，其下用两个 `.rule-group` 区块包裹：

```
pane
 ├─ version card (rv-head)            // 不变
 ├─ .rule-group 编制规则
 │    ├─ 控制基线比例（baseline scope-cards，点卡→解释区）
 │    └─ 编制方式（planMode 单条 flow 项）
 └─ .rule-group 监督规则
      └─ 执行追踪 / 期末余量 / 超预算（trackMode / surplusAction / allowOverBudget 三条 flow 项）
```

实现要点：
- `flowItems(version)` 拆为 `planMode`（编制组）与 `supervise = [trackMode, surplusAction, allowOverBudget]`（监督组）：
  ```js
  const flow = flowItems(version);
  const planMode = flow.find((i) => i.scopeKey === "planMode");
  const supervise = flow.filter((i) => ["trackMode","surplusAction","allowOverBudget"].includes(i.scopeKey));
  ```
- 抽一个 `renderFlowItem(it)` 渲染单条 flow（沿用现 `rv-flow-item` 结构），编制方式、监督三项共用。
- baseline 点卡→解释区（`renderScopeExplain`）仍在编制组内，`pane.querySelector('[data-role=explain]')` 全局可定位，行为不变。
- Tab4 草案预览调用同一函数，**自动同步分组**，无需改 Tab4 其它代码。

### 3.3 不改的部分（范围边界）

- **后端**：不动（无数据模型变化）。
- **`renderCnExtract`（Tab4 抽取对照区）**：本期不改——三类 flow 下拉本就在 baseline 对照下方，逻辑上即"监督规则抽取"，保持现状；如后续要视觉分组可另排。
- **Tab3 适用经济事项**：不动（它用 baseline scope-cards 作为规则卡，无 flow 组概念）。
- **移动端**：暂不同步（既定边界）。
- `planMode` 本期仅"显示归类"到编制组，不进入 AI 抽取（延续上轮"三类 flow 抽，planMode 不抽"决策）。
