# 汇总平衡视图独立化方案

- 日期：2026-08-27
- 背景：用户反馈「上级领导收到下级提交的预算后，进行汇总平衡。把这个页面优化一下。从编制页面去掉平衡预览。然后换个角色，从工作台进入汇总平衡页面展示。」

## 1. 问题与目标

原「汇总平衡」能力以「上级平衡预览」面板形式内嵌在**预算编制页**（`compile.js`）中，存在两个问题：
1. **职责混杂**：编制页的核心是「填报/编制」，而「汇总平衡」是**收到下级提交后上级做的事**，两个角色的工作阶段不同，放在同一页容易混淆。
2. **入口隐蔽**：平衡预览藏在编制页的操作按钮区，上级领导进入系统后不能从工作台直观发现。

目标：
- 从编制页移除平衡预览；
- 将汇总平衡能力独立为「汇总平衡」视图；
- 上级领导登录后，在工作台首页可见直达入口，顶部导航也可见；
- 页面呈现优化：KPI 卡 + 弹性分布 + 分类筛选 + 明细表 + 确认下发。

## 2. 方案对比

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 保留在编制页，仅优化 UI | 不移动，只美化面板 | 改动最小 | 职责仍混杂，入口仍隐蔽 | 否 |
| B. 独立为「汇总平衡」视图 + 工作台入口（选中） | 新建 `balance.js`，注册视图/导航，工作台加卡 | 角色边界清晰，入口自然 | 需新增文件与导航配置 | **是** |
| C. 复用「部门预算汇总」（unit-summary） | 在 unit-summary 里加平衡逻辑 | 已有汇总页面 | unit-summary 侧重「单位 × 事项」矩阵组合，与弹性分类偏离度平衡语义不同，硬塞会污染 | 否 |

选择方案 B：边界清晰，与现有视图/导航体系一致。

## 3. 改动文件

1. `website/views/balance.js`（新建）——独立视图实现。
2. `website/views/compile.js`——删除平衡预览面板与按钮；暴露 `BM.buildCompileSource()`。
3. `website/views/workbench.js`——上级角色工作台显示「汇总平衡工作台」直达卡。
4. `website/core/state.js`——`BM.roleViews()` 对上级角色开放 `balance`；`BM.NAV_LABELS` 增加标签。
5. `website/app.js`——视图路由注册 `balance`。
6. `website/index.html`——引入 `views/balance.js`。
7. `website/styles/v02.css`——新增 `.bal-*`、`.balance-table*`、`.wb-hero-card` 样式。
8. `.workbuddy/module-specs/balance.md`——模块规格。

## 4. 角色与入口

- **可见角色**：boss / ceo / finance / buHead / cooLead / cooAnalyst（与 `BM.canViewBenchmark` 上级集合一致）。
- **入口 1**：顶部导航「汇总平衡」。
- **入口 2**：工作台首页「汇总平衡工作台」直达卡。

## 5. 页面结构

```
汇总平衡 · 2026
├─ 角色责任提示
├─ KPI 卡行：编制总额 / 偏高项 / 偏高涉及金额 / 刚性占比
├─ 弹性分布条
├─ 平衡建议提示
├─ 弹性分类筛选（全部 / 弹性 / 半刚性 / 项目型 / …）
├─ 明细表：经济事项 · 弹性分类 · 本年度预算值 · 建议区间 · 平衡标记 · 平衡动作
└─ 底部：确认平衡结果 → 下发
```

## 6. 数据依赖

- 经济事项数据源：`BM.buildCompileSource()`（优先后端 `/api/events`，离线回退 mock）。
- 建议区间与偏离度：`BM.budgetAdvice()` / `BM.adviceDeviation()`。
- 弹性分类：`balance.js` 内部维护 `BAL_ELASTIC` 字典，与 `compile.js` 原字典保持一致。
