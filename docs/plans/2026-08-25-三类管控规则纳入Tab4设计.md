## 〇、实现说明（2026-08-25 松哥最终拍板「就是下拉框选择一下」→ 简化实现）

原方案（3.1 后端 AI 抽取 `flowProposals` + 3.2 草案内核对下拉）被简化为**纯前端下拉直接选**：
- **不再依赖 AI 抽取三类管控规则**（后端 `extractFlowProposals` 未实现，亦无需实现）。
- Tab4 在「② 抽取对照」之后新增独立区块「监督规则设置（下拉选择，默认继承当前生效版本）」，含 `trackMode / surplusAction / allowOverBudget` 三个 `<select>`，选项取自 `FLOW_META`，默认值 = 当前 active 版本的 flow 值。
- `genBtn` 生成草案时用下拉当前值**覆盖** flow 项（替代原「原样克隆」）。
- 草案生成后改下拉 → `pushFlowOverrides` 实时 PUT 草案 flow 项 + 重渲染预览（所见即所得）。
- `pubBtn` 发布后调用 `BM.syncStateRules(draft)` 把版本化 flow 写回 `BM.state.rules`（含 `planMode`），**修复隐藏双轨不同步**：报销/采购拦截、编制方式等业务逻辑随发布生效。

对齐结论第 2 项（AI 抽取 + 下拉可微调）落实为「下拉直接选」；第 1 项（全公司统一一条）、第 3 项（发布同步生效）**均保持并实现**。

## 一、背景与现状核对（已读代码实证）

本轮需求：预算规则除「编制规则（baseline 控制基线比例）」外，还应包含三类管控规则——
**执行追踪方式 / 期末余量处理 / 超预算处理**；要求它们也进入 Tab4 的生成流、由 AI 抽取、统一发布；Tab1 保留显示当前值。

现状核对（grep + 读 `server/db.js` / `website/views/rules.js`）：

1. **三类规则已存在于数据模型**：它们作为 `budget_rule_item` 的 `flow` 类项 seed 在 active 版本中（`server/db.js:1085-1086`）：
   - `trackMode = reimburse`（实际报销入账追踪）
   - `surplusAction = reclaim`（期末结余收回）
   - `allowOverBudget = false`（不允许超预算）
   - 另有 `planMode = bottomup`（编制方式，本期不抽取，维持克隆原值）
2. **Tab1 已显示这三类**：通过 `flowItems(active)` 渲染「财务流程规则」子区（`rules.js:160-165`，元数据见 `FLOW_META` `rules.js:24-28`）。满足「Tab1 保留显示当前值」。
3. **Tab4 草案生成的真实缺口**：`genBtn` 生成草案时（`rules.js:617-645`），`extractRuleProposals` **只抽 baseline 比例**（带 scopeKey），三类 flow 是从当前版本**原样克隆**（`rules.js:631` `flowItems(dv).forEach(... push 原值)`），**未被 AI 抽取**。即"移到 Tab4"= 让它们进 AI 抽取→核对→发布流。
4. **隐藏双轨（本期必须补）**：业务拦截/追踪逻辑（`website/views/projects.js:116` 超预算拦截 toast、`website/core/state.js:683-685,820` 超预算检查）读的是前端 `BM.state.rules`（state.js 写死的全局对象），与刚发布的版本化 `flow` 项**不同步**。现状下即使发布新版本，业务行为不变——只 Tab1/Tab4 显示变。要让"发布真正生效"必须补同步。

## 三、设计方案

### 3.1 后端：抽取结构扩展（`server/db.js`）

`extractRuleProposals(db, text)` 保持返回 `proposals`（baseline 比例，兼容现有前端），**新增** `flowProposals` 字段：

```js
function extractFlowProposals(text) {
  if (!text) return [];
  const matchEnum = (map) => {
    for (const [val, kws] of Object.entries(map))
      for (const kw of kws) if (text.indexOf(kw) >= 0) return val;
    return null;
  };
  const out = [];
  out.push({ scopeKey: "trackMode", value: matchEnum({
    reimburse: ["实际报销", "报销为准", "据实报销", "报销入账"],
    advance:   ["申请单", "预跟踪", "请款", "预占额度"],
  }) });
  out.push({ scopeKey: "surplusAction", value: matchEnum({
    reclaim: ["收回", "结余收回", "回收"],
    suspend: ["挂起", "暂停占用", "冻结结余"],
    carry:   ["结转", "滚存", "结转下期"],
  }) });
  const ov = matchEnum({
    "true":  ["允许超预算", "可超预算", "放开超", "允许超额"],
    "false": ["不允许超预算", "拦截", "严控", "不得超", "禁止超"],
  });
  out.push({ scopeKey: "allowOverBudget", value: ov });
  return out.filter((x) => x.value != null);
}
```

端点 `POST /api/rule-versions/:id/extract`（`server/server.js`）返回体扩展为：
```json
{ "proposals": [...baseline...], "flowProposals": [{ "scopeKey": "trackMode", "value": "reimburse" }, ...] }
```
`value` 对 `allowOverBudget` 存字符串 `"true"`/`"false"`（与 `budget_rule_item.value` 存储口径一致）。

### 3.2 前端：Tab4 草案抽取 + 下拉可微调（`website/views/rules.js`）

- `runExtract`（`rules.js:610`）：调用后同时取 `proposals`（baseline 对照）与 `flowProposals`，传给 `renderCnExtract`。
- `renderCnExtract(exResult, proposals, baseline, flowProposals)`：在 baseline 对照区下方**新增「三类管控规则（AI 抽取，可核对）」区块**：
  - 对 `trackMode / surplusAction / allowOverBudget` 各渲染一个下拉，选项来自 `FLOW_META[k].options`；
  - 默认选中 = AI 抽到的 `value`（抽不到则选中当前 active 值）；
  - 人可改；改动存 `exResult.flowOverrides = { scopeKey: value }`。
- `genBtn`（`rules.js:617`）：生成草案时，除 baseline apply 外，把 `flowOverrides`（或 flowProposals 默认值）覆盖进 `items`：
  ```js
  flowItems(dv).forEach((it) => {
    const v = (exResult.flowOverrides && exResult.flowOverrides[it.scopeKey] != null)
      ? exResult.flowOverrides[it.scopeKey] : it.value;
    items.push({ scopeKey: it.scopeKey, value: String(v) });
  });
  ```

### 3.3 前端：发布同步业务 state（关键生效点）

`pubBtn` 发布成功（`rules.js:647`）后，除 `BM.loadRuleVersions()` 重载版本，新增 `syncStateRules(active)`：

```js
function syncStateRules(active) {
  if (!active) return;
  const flow = flowItems(active);
  const get = (k) => { const it = flow.find((i) => i.scopeKey === k); return it ? it.value : null; };
  BM.state.rules = BM.state.rules || {};
  const t = get("trackMode"); if (t) BM.state.rules.trackMode = t;
  const s = get("surplusAction"); if (s) BM.state.rules.surplusAction = s;
  const o = get("allowOverBudget");
  if (o !== null) BM.state.rules.allowOverBudget = (o === "true" || o === true);
}
```

使 `projects.js` 的超预算拦截、`state.js` 的追踪/超预算检查**随发布版本切换**；否则发布只是展示层变更。
