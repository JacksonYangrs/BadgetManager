## 一、需求与已拍板决策

### 1.1 需求
- 新增「**基础数据管理**」功能 + 页面，对基础数据做 **增 / 删 / 改 / 调整**。
- 基础数据对象：**经济事项**、**会计科目**。
- 规则部分：复用已有的「预算规则版本管理」（`rules.js`），**保持独立页面**（顶部「预算规则」入口 `#rules`），**不并入**基础数据管理聚合页。

### 1.2 已拍板决策（AskUserQuestion 2026-08-24）
- **D-A 页面结构 = 聚合页 + 子 Tab**：单一「基础数据管理」页，内部 Tab 切换 `经济事项 | 会计科目`；规则版本管理（`rules.js`）**保持独立页面**（顶部「预算规则」入口 `#rules`），**不并入**聚合页。
- **D-B 会计科目 = 独立科目主数据表**（`account_subject`）：松哥拍板不走"并入 economic_event"，要规范化独立表。
- **D-C 维护范围 = 经济事项 + 会计科目**（基础数据管理聚合页）；**规则版本管理**：已有 `rules.js` 独立页面，本轮仅将入口标签由「财务规则」改为「预算规则」并保持独立，不重做、不并入；**组织单位（公司/部门/中心）本轮不做**。
- **D-D 维护权限 = `admin`(默认全权) + `finance` + `centerOwner`(按中心隔离) + 总办(`cooLead`/`cooAnalyst`)**。
  - 角色实证：`website/data/data.js:83-96` 已定义 `cooLead`(总经办负责人)、`cooAnalyst`(总经办预算管理员)，scope=group，正是规则引擎/导入核对/汇总的职责方，给维护权合理。

## 二、数据模型设计

### 2.1 新建 `account_subject`（会计科目主数据表）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| code | TEXT UNIQUE | 科目编码（原 `economic_event.acct_code` 去重） |
| name | TEXT | 科目名称 |
| cat | TEXT | 经济事项分类 / 大类 |
| center | TEXT | 预算归口部门（关联 organization 的 center 节点，如 总办/财务/IT…） |
| method | TEXT | 控制方法 type（down5/canteen/dorm/revenue/green/actual/volume/qtyPrice/history/manual） |
| control_logic | TEXT | 控制逻辑文字（如"较2025实际下降5%"） |
| parent_id | INTEGER | 分级父节点（本轮先留 NULL，做扁平） |
| sort_no | INTEGER | 排序 |

### 2.2 `economic_event` 调整（不改表名/目录，仅加字段）
- 新增 `subject_id INTEGER`（FK → `account_subject.id`），作为经济事项归属科目的正式外键。
- **保留 `acct_code` 字段**作为兼容冗余（已有 81 条数据 + 多处引用），新增 `subject_id` 为正式关联。
- `cat` 保留为经济事项名（一行事项 = 某科目下的一条编制记录）。

### 2.3 关系建模（待定稿确认）
- **推荐 1:N**：`account_subject`(1) — `economic_event`(N)。科目是主数据，一个科目下可有多个经济事项（不同公司/场景的编制行）。更符合"科目主数据 + 经济事项"语义。
- 备选 1:1：若 `cat` 即科目名，则一一对应。但现有 81 条事项的 `cat` 各不相同（事项级），不支持 1:1，故推荐 1:N。

### 2.4 迁移（T1 已有 81 条数据）
- 从现有 `economic_event.acct_code` 去重生成 `account_subject`（code + name + center + method + control_logic）。
- 回填 `economic_event.subject_id`。
- 调整 `scripts/import_excel_data.py`：导入顺序改为 **先建科目主数据 → 再建经济事项并关联 subject_id**（保持幂等）。

## 三、后端 API 设计（新增 / 改动）

### 3.1 会计科目 CRUD（新增）
| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/api/subjects` | 科目列表（可按 center/method 过滤） | 登录 |
| GET | `/api/subjects/:id` | 单条 | 登录 |
| POST | `/api/subjects` | 新增科目 | 基础数据维护角色 |
| PUT | `/api/subjects/:id` | 改科目 | 基础数据维护角色 |
| DELETE | `/api/subjects/:id` | 删科目（校验无引用事项，否则拦截） | 基础数据维护角色 |

### 3.2 经济事项 CRUD（新增 增/删/改本体）
| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | `/api/events` | 新增事项（含 subject_id / cat / center / method / 金额） | 基础数据维护角色 |
| PUT | `/api/events/:id` | 改事项本体 | 基础数据维护角色 |
| DELETE | `/api/events/:id` | 删事项 | 基础数据维护角色 |
| （保留） | GET/PUT amount/PUT monthly | 既有编制接口不动 | — |

### 3.3 权限中间件
- 新增 `requireBaseDataEditor(req,res,next)`：`roles` 含 `admin|finance|cooLead|cooAnalyst` 直通；`centerOwner` 仅当操作的 `center` 与其 `scopeCenter` 匹配时放行；否则 403。
- 规则版本已有 `requireRuleEditor`（admin/finance），作为独立页面 `rules.js` 沿用，不并入基础数据管理。

### 3.4 规则版本（已有，整合不复做）
- 复用 `/api/rule-versions*`（克隆/改因子/发布/抽取/回滚），前端 `rules.js` 为**独立页面**（顶部「预算规则」入口 `#rules`），不并入基础数据管理聚合页。
