# 组织架构可编辑 + 图形化（设计文档）

> 状态：✅ 已定稿 / 开发完成（2026-08-24）
> 验证：`tests/api/org_crud.test.cjs` 14/14 通过；`tests/e2e/org_editable.e2e.cjs` 10/10 通过。
> 关联：基础数据管理（经济事项/会计科目）已上线；本方案在其上新增「组织架构」可编辑能力。

## 1. 背景与目标
当前 `organization` 表（`id, code 唯一, name, parent_id, level`）仅有种子数据（总部 HQ + 4 个公司），`org.js` 是**全员只读**的缩进树，后端**无任何组织写接口**。
目标：把组织架构升级为**可编辑的基础数据**——支持改名、调整隶属关系（改 parent）、新增/删除节点，并以 **SVG 组织图**（方框+连线）图形化展示，点击节点即编辑。

## 2. 对齐结论（2026-08-24 拍板）
| 决策点 | 结论 |
|---|---|
| 放置位置 | 基础数据管理页 **第 3 个 Tab**（与 经济事项/会计科目 并列） |
| 图形化形态 | **SVG 组织图**：自上而下方框层级图，节点间连线，点击节点即编辑 |
| 编辑权限 | **管理员 + 总经办**（admin / cooLead / cooAnalyst） |
| 删除策略 | 允许删除，但**带拦截**（节点下若有预算数据 / 人员 / 子节点则拦截并提示） |

## 3. 数据模型
- **不改表结构**：`organization` 已有 `parent_id` / `level`，足够支撑。
- 新增后端函数（`server/db.js`）：
  - `getOrg(id)`、`listOrgsFlat()`（现有 `listOrgs` 复用）
  - `createOrg(body)`：校验 `code` 唯一；`parentId` 可空（根）；插入后按深度重算 `level`
  - `updateOrg(id, body)`：**改名** + **改 parent_id**；改 parent 时做**环检测**（新父不能是自身的后代）；按深度**重算 level**
  - `deleteOrg(id)`：**拦截**——若 `children>0` 或 `unit_budget` 有 `org_id` 引用 或 `users` 有 `org_id` 引用，返回错误（类比科目"被引用不能删"）
  - 辅助：`recomputeLevel(id)`（深度：0=group, 1=company, ≥2=dept）、`isDescendant(a, b)`（环检测）
- `level` 语义：由深度**自动推导并重算**，避免手工 level 与树不一致（v1 不暴露手工 level 编辑）。

## 4. 后端 API（`server/server.js`）
- 现有 `GET /api/orgs`、`GET /api/orgs/tree`：保留（tree 供前端 SVG 布局用）。
- 新增（均需 `auth` + `requireOrgEditor`）：
  - `POST /api/orgs` → `createOrg`
  - `PUT /api/orgs/:id` → `updateOrg`（含环检测 + level 重算）
  - `DELETE /api/orgs/:id` → `deleteOrg`（含拦截）
- 新增中间件 `requireOrgEditor`：仅放行 `admin / cooLead / cooAnalyst`（与 `requireBaseDataEditor` 区分：后者含 finance/centerOwner，本模块不含）。
- 错误统一返回 `{error:"…"}`，前端 toast 展示。

## 5. 前端
### 5.1 SVG 组织图渲染器（共享组件）
- 新建 `website/views/orgchart.js`：输入扁平 `orgs`（含 parent_id），构建树 → 计算自上而下布局（每个节点方框 + 父子连线 SVG path）→ 返回 DOM。
- **编辑模式**：节点方框可点击 → 弹出编辑模态；节点旁显示「＋新增子级」「✎改名」「🗑删除」按钮（仅 `canEditOrg` 时渲染）。
- **只读模式**：同渲染器但不渲染按钮（供全员查看页复用）。

### 5.2 基础数据第 3 Tab（可编辑）
- `website/views/basedata.js`：聚合页新增「组织架构」Tab（tab 切换 + 渲染 `orgchart` 编辑模式）。
- 编辑按钮显隐由 `BM.canEditOrg()` 控制（admin/cooLead/cooAnalyst 为 true；finance/centerOwner 仅看 SVG、无编辑按钮——保持与"编辑权限"决策一致）。
- 编辑模态字段：
  - 名称（改名）
  - 隶属上级（下拉：除自身及自身后代外的所有组织，防环）
  - 操作：新增子级 / 删除（删除触发 `DELETE`，后端拦截时 toast 提示原因）

### 5.3 独立组织架构页（全员只读，防回归）
- 升级现有 `website/views/org.js` → 改用 `orgchart` **只读模式**（SVG 图形化），保持**全员可见**（不收进 5 角色的基础数据页，避免普通员工看不到组织图）。
- 权限：`roleViews` 中 `org` 维持现有全员可见；只读、无编辑入口。

## 6. 权限矩阵
| 能力 | admin | cooLead | cooAnalyst | finance | centerOwner | 基层/员工 |
|---|---|---|---|---|---|---|
| 查看组织图（SVG） | ✅ | ✅ | ✅ | ✅ | ✅ | ✅（独立页） |
| 编辑组织（改名/调隶属/增删） | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |

> 说明：基础数据页对 finance/centerOwner 可见（经济事项/会计科目 可编辑），但其中「组织架构」Tab 的编辑控件仅 admin/总经办 出现；全员另可通过独立「组织架构」页查看图形化组织图。

## 7. 风险与防护
1. **删除悬空**：`deleteOrg` 拦截 children / unit_budget / users 引用——必做。
2. **环检测**：改 parent 时拒绝把节点挂到自身后代下——必做。
3. **level 一致性**：每次改 parent 重算深度→level，杜绝 group/company/dept 错层。
4. **预算影响**：改名不影响预算（`unit_budget` 按 `org_id` 关联，不按 name）；调隶属不改变 `org_id`，仅改变展示层级——预算聚合口径不受影响（如需按新层级聚合另议，本方案不动预算计算）。
5. **编码红线**：所有写操作补回归测试（API 单测 + Playwright E2E）；真机验证后端拦截后再宣称完成。

## 8. 验证计划
- **API（curl/pytest）**：创建节点→改 parent（含环拒绝）→level 重算核对→删除（有 unit_budget 引用时拦截、无引用时成功）。
- **E2E（Playwright）**：admin 登录→基础数据→组织架构 Tab→SVG 渲染、编辑按钮可见；finance 登录→同 Tab 编辑按钮**不可见**；删除有预算的节点被拦截并提示。
