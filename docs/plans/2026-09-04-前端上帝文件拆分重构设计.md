## 1. 背景与目标

审计识别出前端 5 个「上帝文件」（>600 行且多职责混装、顶层 `function` 污染全局作用域）：

| 文件 | 行数 | 问题定性 |
|---|---|---|
| `website/data/data.js` | 1486 | 数据字典 / 流水生成 / 规则引擎 / AI 编制建议 / 看板数据层 混装，唯一 `buildRuleAnalysis` 顶层函数泄漏全局 |
| `website/core/state.js` | 803 | 状态核心 / 预算访问 / 权限闸门 / 16 组业务动作混装，8 个顶层函数泄漏全局 |
| `website/views/plan.js` | 1120 | 4 个子视图（意图解析 / 自上而下 / 自下而上 / 客户规则引擎）混装，15 个顶层函数泄漏全局 |
| `website/views/dashboard.js` | 653 | 7 个维度 body 渲染 + 图表混装，15 个顶层函数泄漏全局 |
| `website/views/rules.js` | 829 | 已 IIFE 隔离（M11 修复），内部 Tab 结构清晰，本次不拆 |

**目标（方案 A）**：
1. **保持 `window.BM` 全局命名空间不变**——40+ 视图与 `app.js` 的 `BM.xxx` 调用**零改动**，对外 API 签名与语义完全一致。
2. **按职责域拆分超大文件**，每个文件落到 600 行以内、对应单一限界上下文。
3. **IIFE 隔离**，从根上消除「顶层 `function` 污染全局 + 后加载覆盖先加载同名函数」的地雷（`renderEventsTab` 冲突的同类隐患）。
4. **为未来 ES Module 预留边界**：拆分后每文件自包含、只读写 `window.BM`，将来转 `export`/`import` 是纯机械动作。

## 4. IIFE 隔离模式（统一写法）

沿用 `views/rules.js` 已确立的模式（保持全站一致）：

```js
/* 文件头注释：职责域 + 迁移自原文件 + 依赖顺序说明 */
(function () {
  var BM = window.BM || {};
  // ... 仅向 window.BM 挂载本域符号 ...
  window.BM = BM;   // 必须：当 window.BM 尚未建立时，var BM = window.BM || {} 会新建对象，需显式回挂全局
})();
```

- 每个拆分文件**只写 `window.BM`**，不声明任何全局裸 `function`/`let/const`（工具函数要么 IIFE 内私有、要么 `BM.xxx = function`）。
- 原「顶层裸函数」一律迁入 IIFE 私有作用域；对外统一 `BM.xxx`。
- **`window.BM = BM` 在每个拆分文件末尾是必须的**：IIFE 内 `var BM = window.BM || {}` 在 `window.BM` 未建立时会创建**新对象**（不再是 `window.BM` 同引用），必须显式 `window.BM = BM` 回挂，否则本文件挂载的符号不会进全局、下一个文件会各自拿到孤立对象。

## 6. ES Module 预留边界

- 每文件自包含、只经 `window.BM` 出/入（不读他人闭包变量、不隐式依赖加载顺序之外的东西）。
- 未来转 `export`/`import` 时，把每个 IIFE 顶部 `var BM = window.BM || {}` 换成 `import { ... } from "./xxx.js"`、把 `BM.xxx = ...` 换成 `export const xxx = ...`，即可逐文件机械迁移，无需重写逻辑。
- 本次**不引入** ES Module / 打包器（方案 A 明确「预留边界」而非「立即迁移」，避免 40+ 视图 `BM.xxx` 调用与 `index.html` 大面积改动）。
