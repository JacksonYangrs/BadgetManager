# 模块设计文档：ai-policy-extract（政策抽取）

## 一句话定位
把「政策文件」自动读成「可落地的规则建议」，让外部政策（如「今年办公费压降 10%」）能进系统。

## 业务说明
上面有「规则」模块，但规则从哪来？很多来自政府文件、集团发文。这个模块负责把政策原文「读」成结构化建议：

- 抽取：未来接大模型，把政策文本解析成「适用于什么范围、压降多少」的建议。
- 落库：政策原文和抽取结果都存下来，供规则模块复用。
- 谁会用到：管理员上传政策 → 系统出建议 → 人工审核后转成正式规则。
- 为什么存在：政策是预算口径的重要来源，手动抄容易错、容易漏，自动化抽取更稳。

## 业务流程（业务视角）
1. 抽取：粘贴/上传政策文本 → 系统（未来经 AI）解析出规则建议。
2. 映射：把自然语言 hint 映射到规则作用域（scope）。
3. 落库：保存政策原文 + 抽取结果，后续由规则模块采纳。

## 技术对口（速查）
- 文件：`server/modules/ai-policy-extract.js`
- 数据库表：`policy_document`（政策原文 + 抽取结果）
- 关键能力：`extractRuleProposals`、`hintToScope`、`savePolicyDocument`、`HINT_SCOPE`

## 依赖与解耦
- 依赖入：无（纯函数 + 表）。
- 依赖出：前端「政策抽取」页调用；与 rules 共享 policy_document 表。
- 共享资源：`policy_document` 表。
- 目标耦合度：松。解耦措施：不依赖 rules 模块，仅在表层面共享，避免循环依赖。

## 关键决策规则
- 抽取产生的是「建议」，不是直接写规则——必须经人工/规则层校验（verifier），符合「规则只作护栏」。
