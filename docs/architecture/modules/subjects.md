# 模块设计文档：subjects（费用科目 / 归口字典）

## 一句话定位
维护「费用科目」字典——把乱七八糟的费用，归类成可统计、可归口、可控制的科目。

## 业务说明
行政费用名目繁多（办公费、食堂、宿舍、差旅、绿化……），系统需要一套统一分类来统计和管控。这个模块就是「费用科目」这本账：

- 科目 = 一类费用的标签，带「归口」（由哪个职能中心负责）、「控制逻辑」（怎么管这笔钱）。
- 它最初从已有的经济事项自动提炼出来（去重生成），之后可手动增删改。
- 谁会用到：归口责任人（行政归口）维护科目；编制/导入时按科目归类；报表按科目聚合。
- 为什么存在：没有科目，费用就是一堆无法归类、无法对比、无法压降的数字。

## 业务流程（业务视角）
1. 初始化：从已有经济事项里把出现的费用名目去重，自动生成科目（幂等）。
2. 日常：管理员新增/修改/停用科目，设置它归哪个中心、用什么控制方式。
3. 引用保护：科目下还有费用记录时，不允许删除，避免数据断裂。

## 技术对口（速查）
- 文件：`server/modules/subjects.js`
- 数据库表：`account_subject`（code/name/cat/  center/method/control_logic/sort_no）；关联 `economic_event`
- 关键能力：`listSubjects`、`createSubject`、`updateSubject`、`deleteSubject`、`migrateSubjects`、`getSubject`

## 依赖与解耦
- 依赖入：仅 `pure-calc`（预留）。
- 依赖出：被 `events.js`、`expense-import.js` 调用。
- 共享资源：`account_subject`、`economic_event` 表。
- 目标耦合度：松。解耦措施：纯数据层，与规则/AI 无关。

## 关键决策规则
- 科目编码（code）唯一，是字典的钥匙。
- 删除前检查引用数 > 0 则拒绝——科目被费用引用时禁止删除。
