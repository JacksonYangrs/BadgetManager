# 模块设计文档：budget-compile（预算汇总 · 编制汇总）

## 一句话定位
把「各单位、各事项」的预算层层加总，给出按类别、按组织的汇总视图，并承载「压降」这一管理动作。

## 业务说明
编制不是只填一张表，而是要能「看全局」：集团层面要看到每个二级单位、每个费用类别一共编了多少，钱压下来多少。这个模块负责这个「汇总 + 压降」：

- 单位预算：每个（单位 × 经济事项）一条记录，含总额、月度、压降比例/金额、原因说明（note）。
- 汇总：按费用类别把各单位金额相加，看出「钱主要花在哪儿」。
- 压降：管理线降本的两大手段之一（另一个是事业线下达）——给某类费用规定压降比例，系统记录并追踪。
- 谁会用到：总经办/财务做汇总对标；管理层看压降落实。

## 业务流程（业务视角）
1. 读取：拉取所有单位×事项的预算，附月度与压降字段。
2. 聚合：按费用类别把金额加起来，算出压降总额。
3. 压降：保存「压降比例/金额 + 原因」，作为管理动作留痕。

## 技术对口（速查）
- 文件：`server/modules/budget-compile.js`
- 数据库表：`unit_budget`（org_id/event_id/amount/last_budget/last_year/monthly/reduce_ratio/reduce_amount/note）；关联 `budget_execution`
- 关键能力：`listUnitBudgets`、`summaryByCat`、`updateUnitBudgetReduction`、`ubRowToEvent`

## 依赖与解耦
- 依赖入：仅 `pure-calc`。
- 依赖出：被前端「编制/预算跟踪」页调用。
- 共享资源：`unit_budget`、`budget_execution` 表。
- 目标耦合度：松。解耦措施：仅纯计算/数据，不碰规则与 AI。

## 关键决策规则
- 压降（reduce）是管理线维度，与「事业线下达」并列；原因写进 note 持久化。
- 单位数量按组织树自动确定，不写死。
