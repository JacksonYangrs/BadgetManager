# 模块设计文档：organization（组织管理）

## 一句话定位
管理「集团 → 二级单位 → 部门 → 管理中心」的组织树，是整个预算系统「按组织归集、按层级审批」的地基。

## 业务说明
行政费用预算是分级管理的：集团总部往下有若干二级单位（如各公司），二级单位下挂部门，另外还有跨公司的「职能中心」负责某类费用归口（比如行政归口统一管理办公费）。这个模块就是这套组织结构的户口本——它回答「这笔费用归哪个单位 / 哪个部门 / 哪个中心管」。

- 它做三件事：① 维护组织层级（总部、二级单位、部门、管理中心）；② 给每个组织节点打上「管理中心归属」，让一个中心能管多个部门；③ 提供「我是某组织的上级吗」之类判断，用于审批流和汇总时向上归集。
- 谁会用到：系统初始化时由导入脚本灌入真实组织数据；预算编制时按组织归属归类；审批/汇总时按层级向上汇总。
- 为什么存在：没有它，预算就不知道「谁的钱、谁来批、归谁管」，压降目标也无法按组织层层下达。

## 业务流程（业务视角）
1. 系统首次启动：导入脚本把组织架构（含 11 个管理中心）一次性灌进来。
2. 日常：新增/调整部门、迁移组织类型（如把某部门挂到指定管理中心）。
3. 编制/汇总时：根据组织树自动确定「某单位的下级有哪些」，再据此归集预算，不写死。

## 技术对口（速查）
- 文件：`server/modules/organization.js`
- 数据库表：`organization`（含 level / type / managed_center_id）、`unit_budget`
- 关键能力：`buildOrgTree`（树形）、`inferBuCode`（推断事业部编码）、`isOrgAncestor`（上下级判定）、`resolveManagedCenter`（解析归属中心）、`listChildUnits`、`recomputeOrgLevels`

## 依赖与解耦
- 依赖入：无（仅 Node 原生）。
- 依赖出：被 `auth.js`、`events.js`、`budget-compile.js` 等调用。
- 共享资源：`organization`、`unit_budget` 表。
- 目标耦合度：松。解耦措施：纯数据 + 纯函数，不依赖任何业务模块。

## 关键决策规则
- 组织层级由 type（group/unit/dept/center）表达，不靠写死层级数量。
- 「一个中心管多个部门」用 managed_center_id 表达一对多，避免重复建模。
