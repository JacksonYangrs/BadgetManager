# 模块设计文档：budget-execution（预算执行 · 实际发生）

## 一句话定位
记录「实际花了多少」，和「计划花多少」放在一起对比，告诉管理层「偏差在哪」。

## 业务说明
编了预算，钱在实际发生时要记录进来，才能知道「预算准不准、有没有超」。这个模块就是「实际账」：

- 执行数据按月度、按（单位×事项）记录实际金额。
- 和「编制」（events / budget-compile）对照，就能算出偏差——哪个事项超了、哪个省了。
- 谁会用到：费用岗/财务录入实际；管理层在「预算跟踪」看执行偏差。
- 为什么存在：预算的价值在于「编制 → 执行 → 对比 → 改进」的闭环，没有执行记录，闭环断掉。

## 业务流程（业务视角）
1. 初始化：建表 + 灌入演示数据（幂等）。
2. 录入：按「单位 + 事项 + 月份」写入/更新当月实际发生额（upsert）。
3. 查询：跟踪页拉出执行列表，和预算做偏差对比。

## 技术对口（速查）
- 文件：`server/modules/budget-execution.js`
- 数据库表：`budget_execution`（org_id/event_id/month/amount）
- 关键能力：`initExecutions`、`seedExecutions`、`upsertExecution`、`listExecutions`

## 依赖与解耦
- 依赖入：无（仅 db）。
- 依赖出：被前端「预算跟踪/执行」页调用。
- 共享资源：`budget_execution` 表。
- 目标耦合度：松（零扇出）。解耦措施：纯数据层，独立演进。

## 关键决策规则
- 执行按月维度，与 budget-compile 的 monthly 口径对齐，便于偏差计算。
- 真实导入落库口径待「数据对齐」阶段确认（expense-import.commit 当前仅校验、未写库）。
