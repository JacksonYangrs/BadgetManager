### 开发中遇到的关键坑（复用知识）
1. **浏览器全局 `const` 重复声明** → 多个 JS 文件顶部用 `const BM = window.BM || {}` 在浏览器全局作用域冲突 SyntaxError。**修复**：全部用 `var BM = window.BM || {}`（var 允许重复声明）。Node 测试时每文件独立模块所以不暴露。
2. **BM.state 引用断裂** → `let state = null; BM.state = state; loadState()` 后 BM.state 仍指向旧 null。**修复**：loadState/resetState 内同步 `BM.state = state`。
3. **意图优先级** → "为什么今年办公用品超预算" 同时含"为什么"+"超预算"，如果预测意图在前会抢先拦截。**修复**：分析 → 建议 → 预测，特判先于泛判。
4. **数据自洽** → IT 设备已用+冻结超预算后，调剂金额必须保证后续采购能通过，否则演示断裂。**设计原则**：故事先验算闭环数字，再写卡片文案。
5. **Headless 渲染验证**：用 `~/Library/Caches/ms-playwright/chromium_headless_shell-1234/.../chrome-headless-shell --headless --screenshot` 做冒烟测试，控制台加 `--enable-logging=stderr --v=0` 看错误。
6. **Copilot 函数未挂载**：copilot.js 中 renderWelcome 是局部函数未挂 BM，app.js 调用报 not a function。**修复**：文件末尾 `window.BM.renderWelcome = renderWelcome;`

用户实测三个问题：①切换角色没反应 ②菜单太多重复 ③AI Copilot 点不动。

### 根因
**app.js `init()` 中事件绑定写在登录态检查 `if (!loggedIn) { renderLogin(); return; }` 之后**——未登录时提前 return，顶栏"切换角色"、"AI Copilot"主 Tab、重置等事件全部未绑定 → 点了没反应。

### 修复
1. **事件绑定前置**：把发送/主 Tab/切换角色/重置的事件绑定全部移到登录态检查之前（先绑定，再决定显示登录页还是主界面）。
2. **去重导航**：删除顶栏 `quicknav`（横排重复菜单，只剩左侧竖排）；删除工作台首页"常用功能"快捷卡片层（`buildQuicks` 函数及渲染），保留欢迎条+待办+AI关注。
3. **验证**：用 CDP 协议（headless chrome `--remote-debugging-port` + Node WebSocket + Runtime.evaluate）在真实 index.html 上模拟点击，全链路通过：
   - 登录→进入（boss 标签正确）
   - 切 AI Copilot Tab（className 变 `app-root copilot`、面板显示）
   - 切换角色→重新选员工进入（标签"员工 · 张伟（IT 部）"、导航 3 项）
   - 重置→回登录页

### 教训
- **浏览器事件绑定必须独立于登录/初始化分支**：init 里 `return` 之前的代码都不执行，事件绑定一旦放在条件 return 之后就成了死代码。结构：先绑事件 → 再判断状态渲染首屏。
- 临时 e2e-test.html（简化复制页）出现 `BM.renderLogin undefined` 的假象，直接改用 CDP 验证真实页面更可靠，删除了该测试页。

## 手机版按钮风格区分（用户"按钮风格区分"）

### 改动
- `.view-tab` / `.flow-node`（切换器 chips）：浅灰底 `var(--c-surface-2)`、无边框、灰字；选中=深蓝实底白字加粗。**像 iOS segmented control**，纯"选择"语义。
- `.btn`（操作按钮）：保留实色填充（accent 金色渐变 + 阴影、primary 深蓝、outline 白底边框）+ 按压 `transform: scale(0.96)` 反馈。
- `.sug-btn`（聊天推荐问题）：改虚线边框 + →箭头，像"对话气泡"，与实色操作按钮区分。
- `.btn-accent` 加金色阴影，强化主操作按钮存在感。

### 视觉语言总结
| 元素 | 语义 | 视觉特征 |
|---|---|---|
| 切换器（chips/流程节点） | "切到哪个" | 浅灰胶囊，无边框，选中深蓝实底白字 |
| 操作按钮（btn） | "去执行" | 实色/边框方角，按压缩放反馈 |
| 推荐问题（sug） | "对话入口" | 虚线边框 + 箭头 |
| 风险卡 | "预警通知" | 左边色条 + 圆形图标 |

### 验证
- 4 张截图（预算总览 / 编制 / Copilot / 主页）确认三种风格明显区分
- 同步 demo/mobile/ 并 push，线上已部署

### 教训
- 用户视觉感知："长得像"的根本原因是 outline 按钮白底灰边 vs view-tab 白底灰边——表面差异只有圆角和 active 态。**用浅灰底区分比用边框/圆角更有效**（一眼看出"虚/实"）。
- 切换器加按压反馈（`.view-tab:active`）让交互有触感，避免与按钮混淆。

## 手机版导航层级区分（用户"一级菜单 vs tab 视角要区分，带视角二字"）

### 改动
- 新增 `.nav-tabs` / `.nav-tab` 样式：**一级菜单导航条**——下划线式 tab，选中金色下划线 + 深色加粗，类似 iOS 顶部导航。
- `budget.js` 一级菜单（预算总览/编制/追踪/决算/规则/调整）改用 `nav-tab` 类。
- `budget.js` 视角 chips 全部加「视角」后缀：科目视角/项目视角/物料视角/部门视角/人员视角。
- 追踪页三态筛选（全部 N/当前超预算 N/当前有结余 N/预计有结余 N）保留 view-tab 胶囊（它是筛选，跟视角同级胶囊合理）。

### 视觉语言体系（最终）
| 元素 | 样式 | 语义 |
|---|---|---|
| **底部 Tab**（首页/预算/审批/AI 助手） | 图标+文字，active 金色图标 | 应用主导航 |
| **一级菜单**（预算总览/编制/追踪…） | 文字 tab + 金色下划线 | 页面内功能分区 |
| **二级视角**（科目视角/项目视角…） | 浅灰胶囊，选中深蓝实底 | 数据维度切换 |
| **筛选 chips**（全部/超预算/结余） | 同二级视角胶囊 | 数据筛选 |
| **操作按钮**（提交/终审/报销） | 实色方角，按压缩放反馈 | 去执行 |
| **推荐问题**（Copilot） | 虚线边框 + →箭头 | 对话入口 |

### 教训
- 用户对"层级感"很敏感：相同 view-tab 类放两类东西（页面导航 vs 数据维度），即使位置不同也混淆。**用样式区分层级**（下划线 vs 胶囊）比靠位置/字号更可靠。
- 视角 tab 加「视角」二字是直接命名上的"语义锁定"，比单独靠样式更明确。
