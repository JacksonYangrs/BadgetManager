## T6 规则向导 bug 修复 + T5 E2E 收尾（续前会话）
- 现象：浏览器向导改 down5=93%→发布，新生效版本 down5 仍为 0.95（curl 直接调同一接口却 OK）。
- 根因：`BM.authHeaders()` 只返回 `Authorization`，**缺少 `Content-Type: application/json`**；后端 `express.json()` 仅在该头存在时才解析 body → 浏览器 PUT/POST 的 JSON body 被静默丢弃，`updateRuleItems` 收到 `items=undefined` 走空数组分支，返回 `{ok:true}` 但零写入。（克隆 POST 因不依赖 body 故"看似成功"，掩盖问题。）
- 修复：`website/app.js` 的 `BM.authHeaders` 与 `website/views/rules.js` 的兜底定义，均补上 `"Content-Type": "application/json"`。前端静态文件，无需重启 server。
- 验证：浏览器复现脚本（捕获网络请求）确认 PUT 体含 down5=0.93 且发布后 active=v2026.1 down5=0.93；修复后复现 active down5=0.93 ✅。
- E2E 全绿：`e2e_smoke.py`（staff 过滤/ admin 可见/ 规则页 v2026.0/ 真实组织 42 公司 16 事业部 17 中心 全部 PASS）、`e2e_rules_wizard.py`（down5=0.93 + 还原 v2026.0 PASS）。
- 终态：DB 仅保留 v2026.0 active（down5=0.95），清理了测试产生的临时版本与调试脚本。T1-T6 全部完成。
- 经验：本项目的 PUT/POST fetch 必须带 `Content-Type: application/json`（其他视图 compile/accounts 等都显式带了，rules 向导漏了）。新增 JSON 写接口时优先复用 `BM.authHeaders` 而非手写 headers，避免再漏。

## 修复「微调分布」分隔线无法拖动（2026-08-24 晚）
- 反馈：松哥截图反馈"无法滑动"。
- 根因：重设计 `monthly-split.js` 时，`render()` 同步了各月段宽度（`segs`），但**漏了同步分隔线位置（`divs`）**。拖动后 divider 仍停在旧位置，下一帧按旧位置计算累积占比，表现为"拖不动"。
