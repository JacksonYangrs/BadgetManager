## 1. Demo 目标

Demo 是后续正式产品开发的**可执行产品参照**。它只回答一个问题：

> 同样的预算数据，传统 ERP 只能记录，我们的 AI 平台能提前发现问题、解释原因、给出方案、自动执行。

成功标准（10 分钟讲完）：

1. 观众能清楚说出与传统 ERP 的三个差异点；
2. 每个 AI 结论都能展开证据链、跳转到明细页核对；
3. 完整走通"对话 → 证据 → 建议 → 执行"闭环，无需切换菜单。

## 2. 设计原则（Blueprint 五原则 → Demo 落点）

| Blueprint 原则 | Demo 如何体现 |
|---|---|
| AI First，而非 ERP First | 首页唯一入口是 AI Budget Copilot，无菜单导航 |
| 决策优先，而非数据优先 | 每个回答给出"结论 + 建议"，不只是一堆数字 |
| 主动服务，而非被动查询 | 开场即推送"今日风险卡片"，不等用户问 |
| 自然语言交互，而非菜单驱动 | 一切操作从一句话开始 |
| 持续学习，而非固定规则 | 决策中心展示"建议被采纳/忽略"的反馈闭环 |

## 3. 信息架构

```text
AI Budget Copilot（唯一入口）
  ├── 事前 · 预测主线（哪个部门会超？何时超？）
  ├── 事中 · 执行主线（一句话发起采购/报销）
  └── 事后 · 分析主线（为什么超了？合理吗？）
        │
        └── 支撑页面（AI 结论的可见证据）
              ├── 预算总览看板
              ├── 部门 / 科目明细
              ├── 审批中心
              └── 决策中心
```

支撑页面从 Copilot 跳转进入（点击证据卡片），也可从顶部快捷入口访问，但**首页永远先出现 Copilot**。

## 4. 页面清单

### 4.1 AI Budget Copilot（首页 · 唯一入口）

- **欢迎态**：产品名 + 一句话定位（"企业行政预算的智能管家"）+ 预置 3 个推荐问题 + 今日风险卡片（自动主动预警）。
- **对话态**：消息流支持以下卡片类型：
  - 预测卡：科目/部门、预计超支比例、预计超支月份、置信度；
  - 分析卡：归因解释（结构化：因素 → 影响 → 结论），标记"合理增长/异常"；
  - 建议卡：预算调剂、统一供应商、调整采购周期等，带"采纳 / 忽略"按钮；
  - 执行卡：AI 已生成的单据（采购申请/审批流），显示审批链路。
- **每条 AI 回复附"证据链"**：数据来源 → 计算依据 → 置信度 → 反证 → 「查看明细」跳转。

### 4.2 预算总览看板

- 顶部 KPI：总预算、已用、已冻结、剩余、整体执行率。
- 部门维度表：各部门年度预算、已用、执行率、预测状态（正常/预警/超支）。
- 科目维度表：各科目执行率 + AI 预测（如"车辆维修预计 11 月超支 18%"）。
- 未来 3 个月预测曲线（基于趋势外推，标注置信区间）。

### 4.3 部门 / 科目明细

- 钻取层级：部门 → 科目 → 单据流水。
- 单据字段：日期、类型（采购/报销/合同付款）、供应商、金额、预算科目、经手人、状态（草稿/审批中/已付款）。
- 从 AI 结论一键直达对应筛选结果。

### 4.4 审批中心

- **AI 初审**：每张单据 AI 预判（通过 / 驳回 / 转人工），附理由（预算充足性、供应商历史、合规检查）。
- **人工终审**：通过 / 驳回，记录审批人。
- 列表含"AI 初审意见"列，体现 AI 初审 → 人工终审流程。

### 4.5 决策中心

- AI 建议列表：类型（预算调剂 / 统一供应商 / 采购周期调整 / 削减 / 增加投入）、目标、预计影响、采纳状态。
- 采纳后：自动生成单据（如预算调剂单、采购申请）→ 进入审批流 → 状态可回滚（演示用）。
- 记录"建议 → 采纳 → 结果"，体现持续学习闭环。

## 5. 三条演示主线（剧本化）

### 主线 A · 事前预测（Predict）

> 老板问：哪个部门今年最容易超预算？

1. AI 回复预测卡：**车辆维修预计 11 月超支 18%，IT 设备预计超支 35%**（附置信度）；
2. 展开证据链：历史月均增速 → 供应商报价趋势 → 反证（暂无维修大单）；
3. 点「查看明细」→ 跳转科目明细核对；
4. 追问：怎么解决？→ AI 给建议卡（预算调剂方案）。

**价值点**：9 月就知道 11 月会超，不用等年底。

### 主线 B · 事中执行（Execute）

> 员工说：我要采购 10 台显示器。

1. AI 回复执行卡：判断预算（IT 设备剩余额度）→ 判断审批人（按金额路由）→ 判断供应商（历史供应商 + 价格对比）；
2. 自动生成采购申请 + 审批流 → 通知领导；
3. 跳转审批中心查看 AI 初审意见与流转状态。

**价值点**：一句话完成"判断 + 生成 + 通知"，几乎零人工。

### 主线 C · 事后分析（Analyze + Recommend）

> 老板问：为什么今年办公用品超预算？

1. AI 回复分析卡：员工 +28% → 打印量 +41% → 会议 +35% → 办公用品 +22%，**属合理增长**；
2. 给出建议卡：统一供应商预计降本 8%；打印纸采购周期从每周改为每月；
3. 点「采纳」→ 决策中心生成对应单据。

**价值点**：不是报表，是解释；AI 关注"投入与效果匹配"，不盲目削减。

## 6. 模拟数据设计（要有故事）

预置一家"正在失控"的模拟企业（如 300 人规模公司），数据自洽：

| 科目 | 年度预算 | 状态 |
|---|---|---|
| 车辆维修 | 120 万 | 预警：预计 11 月超支 18% |
| IT 设备 | 80 万 | 高风险：预计超支 35% |
| 办公用品 | 60 万 | 合理：+22%，因员工/打印量增长 |
| 物业费 | 200 万 | 健康：预计节余 12% |
| 培训 | 100 万 | 低执行：预计节余 30%（可调剂给 IT） |

数据要素：

- 部门：行政部、财务部、IT 部、市场部、销售部、人事部；
- 单据：100+ 条流水（跨 1–9 月），每条可追溯到科目与部门；
- 供应商：每科目 2–3 家，含价格与历史用量；
- 审批：不同金额阈值走不同审批人（体现 AI 路由规则）；
- 时间：当前演示时刻设定为 **9 月**，预测目标为 11 月。

所有数据存于浏览器本地（localStorage），提供「重置 Demo」一键恢复。

## 7. 关键交互

- 对话输入 + 卡片点击双通道（不强制念剧本）；
- 每个 AI 结论必须能展开证据链、能跳转明细；
- 建议可采纳/忽略，采纳后自动生成单据，可回滚撤销；
- 演示用"角色切换"：老板视角（提问/看板）+ 员工视角（发起采购），体现两种角色价值。

## 8. 视觉设计

- 基调：专业财务 + AI 科技感；主色深蓝/靛蓝 + 强调金；
- 风险语义色：预警=琥珀、超支=红、健康=绿；
- 布局：左侧 Copilot 对话流，右侧证据/明细卡片联动（桌面宽屏）；小屏上下堆叠；
- 中文为主，预留中英双语开关（Blueprint 面向海外客户场景）。

## 9. 技术方案（初始基线）

- **形态**：纯前端单页应用（HTML/CSS/JS），`python3 -m http.server` 即可运行；
- **数据**：本地 mock 数据 + localStorage 持久化，不连真实 LLM/数据库；
- **Copilot 引擎**：预置规则 + 剧本模板驱动（确定性，保证演示稳定）；预留 LLM 接口位，后期可切换真实模型；
- **目录结构**：

```text
demo/
  index.html
  styles/          视觉系统 + 各页面样式
  data/            mock 数据（预算/部门/科目/单据/供应商/剧本）
  core/            状态管理（预算、单据、建议、审批）
  copilot/         对话引擎（意图解析 → 卡片渲染 → 证据链）
  views/           看板/明细/审批/决策 页面渲染
  scripts/         app 入口、路由、重置
```

## 10. 验收标准

1. 10 分钟内讲完三条主线，全程无需切换菜单；
2. 每个 AI 结论可展开证据链，可跳转到明细页核对；
3. 建议 → 执行 → 回滚闭环完整可走通；
4. 刷新后状态保留，可一键重置；
5. 自由输入任意预算问题（如"培训预算还剩多少""市场部执行率"）均能正确回答。
